# Library Meet

## Introduction

This library integrates the Meet video-conferencing service with Lutece through the `IVirtualMeetingProvider` interface defined by the `module-appointment-virtualmeeting` module.

It provides the following features:

 
* OAuth2 authentication against the Meet external API
* Room creation with auto-generated slugs
* Meeting URL generation from a configurable URL pattern and the room slug

Unlike token-based providers (e.g. LiveKit), Meet uses a single room URL shared by all participants. The `generateParticipantToken()` and `generateViewerToken()` methods return this room URL directly.

## Configuration

Configure the library in the file `WEB-INF/conf/plugins/meet.properties` :

| Property| Description| Default|
|-----------------|-----------------|-----------------|
|  `meet.server.url` | Base URL of the Meet external API| (required)|
|  `meet.server.clientId` | OAuth2 client ID| (required)|
|  `meet.server.clientSecret` | OAuth2 client secret| (required)|
|  `meet.server.scope` | Email address of the user to delegate| (required)|
|  `meet.server.meetingUrlPattern` | URL pattern for the Meet web frontend. The placeholder `{slug}` is replaced with the room slug at runtime.|  `https://meet.example.com/{slug}` |

## Usage

Add the Maven dependency to your site POM:
<dependency><groupId>fr.paris.lutece.plugins</groupId><artifactId>library-suitenumerique-meet</artifactId><version>1.0.0-SNAPSHOT</version><type>lutece-plugin</type></dependency>
The library is automatically discovered as an `IVirtualMeetingProvider` by the `module-appointment-virtualmeeting` module through Spring bean detection. No additional wiring is required.

When `VirtualMeetingService` calls `getParticipantMeetingUrl()` or `getViewerMeetingUrl()` , the Meet provider relies on the default interface implementation which delegates to `generateParticipantToken()` , returning the room URL built from the configured pattern and slug.
